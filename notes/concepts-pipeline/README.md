# inventory_中枢走势组.md 的生成链（表里每个数字都是这几个脚本算出来的）

给复核的人：文档里的引文计数、三档判据、五格，**不是手数的**，是这条链跑出来的。
按顺序跑，读它每步打印的那几行；对不上就是链断了，不是「大概差不多」。

```
rebuild48.py   # 从底稿 + 行片段拼出表格（未标注态）
markfold.py    # 在「」里按语料折行位置插 ↵
addline4.py    # 给每条引文补/改 L课号:行（★ 非幂等，只能跑在未标注态上）
multimark.py   # 行末就地标跨课（复述待看／撞句待看）＋ 汇总行
verifyline.py  # 行号点 ←→ 引文 一一配对，报「对不上 N」
finalcheck.py  # 复算：引文数／命中／跨课／五格
updnum.py      # 用复算出来的数字重写前言与附录（唯一数字源）
```

### 输入（2026-10-01 从 `/tmp` 落进仓）

`inputs/` 里六个文件是这条链的输入：`annot_log.tsv`（`addline4.py` 的**冻结输出**，被 `finalcheck.py`／`updnum.py` 读）、`state5.md` ＋ 四个行片段（`rebuild48.py` 读）。
**原先它们散在 `/tmp`** —— 在我这儿跑得通、**别人跑必炸**，而且 `/tmp` 一清就没了。现在在仓里，可 diff、可复算。

★ **前提：「能复算」还差一样 —— `archive/` 未进仓**（`.gitignore` 里）。语料需与本仓**同相对路径**就位，否则所有脚本第一步就找不到课。这一句必须和复算命令一起说，否则拿到干净检出照样跑不出来。

`finalcheck.py` + `updnum.py` 是**数字的出处**：文档前言里那串数就是 updnum 打印的那串。
改完表格**必须重跑这两个**，否则前言／附录会停在旧数（我犯过：只重跑了 rebuild，前言停在上一版的 228/195/181）。

## 三个已经踩过的坑（改脚本前先看）

1. **写文件必须在所有 splice 之后**。rebuild 脚本里 `open(P,"w")` 如果放在中途，后面追加的行只改了内存里的 list，
   **不会进文件** —— 打印说「概念行 48」，文件里还是 47，而且不报错。
2. **别用切片去改引文**。`s[:-2] + "…"` 这类写法会吃掉结尾的 `」`，表现是引文总数莫名少 2、
   未命中为 0（因为那个「」压根没被当成引文）。改引文一律用整串替换 + `assert count==1`。
3. **行尾的跨课标注每轮被 strip＋重写**（`multimark.py` 的行尾正则）。要往备注里补东西，插在 ` <br>跨课·` **之前**，
   插在后面下一轮直接被吃掉。

## 口径（不是脚本能替你决定的部分）

- 「」只放**逐字**语料引文。自己的话、缩写、省略号引文一律用 **加粗** 或 `“”` —— 放「」里会被计成未命中。
  ★ 这条**原先只在表体里执行过**（那批非语料「」已改成『』），**附录没跟上**：`checkquotes` 跑的是**全文**，2026-10-01 之前报的「都不中 17」＝ 表里引别名表的 3 处（`专有名词`／`离开 / 返回`／`当前讨论的这一级`，前言已披露为「只引别名表 3」）＋ **附录里残留的 14 处**（引聊天原话与自造标签，已改成『』 —— 改的是 `updnum.py` 的 APPENDIX，**源头改，不改成品**）。现在 **都不中 = 3**。
  ★ 教训：表体和附录的括号纪律要**一起**查。只看表内那一档，整个附录的违规都看不见。
- 行号是**构造保证型**：课号来自我的行文，行来自脚本 `find()` 首次出现位。它保证「标注点没错位」，
  **不保证「当初该标这几行」** —— 别把它并进「查过」那一档。
- `addline4.py` 非幂等。重跑整条链请从 `rebuild` 开始，别在标注态上再跑一遍。

## 补：引文自检与叠字统计（2026-10-01 通读欠账两批时新增）

- `checkquotes.py <文件> [--min N]` —— 把文件里每个「」块回语料核（先剥折行标记 `↵`，要求**整块**在**某一课**的合并文本里逐字命中、**不跨课拼**；严格档与「空白归一」档分开报）。
  **默认门槛已从 25 降到 4**：25 本身就是个洞 —— `L99` 那些短判据句整片漏过（把「必须保证中枢的确立」写成「先保证中枢的确立」，25 字门槛下全绿）。**报数必须连门槛一起报。**
- `doubling.py` —— 相邻同字两档**分开报**：通用档 `([一-鿿])\1` 单行尺 ＝ 全库 **103 课／2243 处／1199 行**（多数是正常叠词：好好看／往往／谢谢）；**虚词档**（命中字 ∈ 41 字虚词表）＝ **41 课／352 处／228 行** 才是疑 OCR。去折行尺 2251（多 8 处＝行尾行首撞出的假叠字）。**两档别相加、别互证；绝对数跨组不可比**（各组词场不同）。
- `append_batch1.py` / `append_batch2.py` —— 两批通读增量的**生成脚本**：每条引文先断言逐字命中语料，跨行处自动插 `↵`，行号由脚本算出来写进正文。**改附录一律走脚本，手敲行号必翻车**（我当场写过一个根本不存在的行号，只能当场在群里更正）。

## 第四个坑

4. **`open(P,"w").write(open(P).read() + …)` 会先把文件截空**。Python 先求值左边的 `open(P,"w")` —— 那一刻文件已经空了，右边读回来是空串，整份文档被替换成刚追加的那一段（这次真踩到：正文＋前三个附录全没，靠 `git checkout HEAD -- <文件>` 救回重跑）。**先读进变量，再开写。**

## 坑 5（2026-10-01 修，最险的一条）

**`updnum.py` 一跑就删掉后面全部附录。** 原式子是 `new = lines[:i] + PREAMBLE + lines[j:k] + APPENDIX` —— `k` 取的是**第一个** `## 附录`，之后到文件结尾**整段丢弃**。写它的时候全篇只有一个附录；后来附录二…十一 是另一支脚本追加的，于是这条式子**一跑就把附录三–十一 全删了**：实测 **1566 行 → 114 行，1450 行没了，且不报错**。

而 README 上面那句「改完表格**必须重跑这两个**」，正好就是叫你这么干。**按文档做 = 毁掉成品。**

已修：只替换**第一节**附录，下一节起原样接回；节间分隔（空行／`---`／空行）**确定性重建**（不去猜原来有几个空行 —— 猜法会因 `APPENDIX` 末尾空行的有无整体错位）；另加守卫 **「任何原有的一级标题在新文件里必须还在，否则拒绝写入」**。现在连跑两遍与改前**逐字节相同**（幂等）。

**教训**：链条里凡是「取第一个 X 之后整段替换」的写法，在**只加不改、后续还往里追加**的文件上都是定时炸弹。守卫要写成「原有的标题一个都不许少」，而不是「行数别少太多」—— 标题少了才是丢了整节。
