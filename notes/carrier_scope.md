# 读数能不能搬：载体射程（「点」与「面」）

本件是一条**纪律**，不绑任何一张卡。适用场景：你读到一份读数（别人的或自己的），
要判断**它在另一棵树上还成不成立**。

## 一、一句话

> **同 blob 搬得动「点」的读数，搬不动「面」的读数。**

## 二、两条射程，两样凭据，别混着用

| 凭据（你比的是什么） | 能搬什么 | 不能搬什么 |
| --- | --- | --- |
| **树相等** —— `git rev-parse <rev>^{tree}` 逐位同 | **树里任何读数**都能搬（最强一档） | —— |
| **blob 逐位同** —— `git hash-object <path>` 同一个 sha | 只有**只走这一颗 blob 这条路径**的读数 | 依赖**整棵树**的读数（同树的其它脚本、数据文件、字体…） |

两条都不是"差不多相同"：**必须逐位同**（同一个 sha，现算）。

## 三、怎么判「点」还是「面」

问一句：

> **这颗 blob 逐字节不动的话，这个读数读出来还一样吗？**

- **一样 ⇒ 点。** 例：只 import 这一颗、只走它自己的函数、输入由夹具自造 —— 与同树其它文件无关。
- **不一样，或你说不清 ⇒ 面。** 例：跑整套回归、跨脚本对拍、任何吃到仓里数据文件 / 字体文件 / 目录清单的数。

★ **说不清就按「面」办。** 把面当点搬，正是本条要防的错。

## 四、报数时的六条硬要求

1. **载体写全、写现值。** 是"树 X"还是"blob Y"，**现算**（`rev-parse` / `hash-object`）再写；
   不引别人的复述，也不写"和上次相同"这种相对说法。
   （本队栽过：一个数被从旧回执转录进新回执 —— 对象换了，数没跟着换。）
2. **不许拿"blob 同"代替"树同"。** 你要搬的是「面」的读数时，别人复算复的是**树**，不是你那一格。
3. **数得出才算数**（三级，缺一级就退回上一级）：
   ① **报成员，不报总数** —— 两个不同的集合可以凑出同一个总数；
   ② **分划要写清** —— `13＋6` 这种尾巴不能省；
   ③ **数法可复核** —— 成员数要能从**该格自己的产物**里数出来，并**把那条命令一起写下**。
   ★ 数不出产物的那半 ⇒ 当**未定**写，**别写数字**。
   （少了第 ③ 级，假印证只是从 `19 vs 19` 下沉到 `13 vs 12` —— 形状没变：
   产物在你自己机器上那份私有输出里，读的人**一个名字也拿不到**。）
   ⇒ 一句话格式：**`<总>（<成员分划>，各自数自 <产物> @ <坐标>）`**。
4. **坐标要写得出**（**仓内文件三种写法 (a)/(a′)/(a″) ＋ 评论本体 (b)**，各判各的、不许互串）：
   (a) **仓内文件** ⇒ `<path> @ <ref>[:<blob>]`；判法 = 在**该 `<ref>` 的可达历史**里
       （`git rev-list <ref> --objects -- <path> | grep -F <blob>`）；**找不到 ⇒ 对读者不存在** ⇒ 那半写**未定**。
       ★ **先单独跑一行**（**它的 rc 才可信**：独立命令，不是管道尾巴 —— 管道的 rc 取的是尾巴 grep 的）：
         `git rev-parse --verify -q <ref> >/dev/null` ⇒ 非 0 就是 **ref 取不到**
         （**裸 `<ref>`，别加 `^{commit}`** —— 坐标里出现的是 blob 时它会误诊：`c25043a7^{commit}` rc=1，而那坐标有效；只对**第二栏是 ref** 的坐标跑这行）。
       ★ 「找不到」**两态别并**：`… | grep -c` 下两条路**打印的数一样、管道 rc 也一样**，`set -o pipefail` 也救不了
         （它取最右边那个非零 = grep 的 1）⇒ 分得开它们的只有 **stderr** 或 **`PIPESTATUS[0]`**：
         · **ref 取不到** ⇒ 写「未定 · **本条 ref 取不到**」（去 fetch，或问坐标作者）—— **不是**"它不在"；
         · **ref 在、该 blob 不在它的可达历史里** ⇒ 才是「对读者不存在」。
       ★ 另两问**不许顶**这一格：`--all` 答的是"**别的** ref 上有没有它"；`rev-parse <ref>:<path>` 答的是
         "**现值**是不是它"（现值每推一次就变一次）⇒ **写坐标时写现值（§四.1）· 判的时候判可达**。
   (a′) **不写 `<blob>`** 的坐标（`<path> @ <ref>`）⇒ 只问"该路径在该 `<ref>` 的可达历史里**出现过**"
       —— 判据比 (a) **弱一档**，件里要写明是哪一支。★ **判法有三件事都要做对**：
       · **吃的 `<ref>` 是层1 吐出来的那个名字**（`--symbolic-full-name` 的输出），**不是第二栏的原样文本**。
         ★ 第二栏是短名或裸对象名时两者**不同** —— 现量（名字＝某颗 blob 的 40-hex，仓里**另有**一条同名 tag）：
           `rev-list 'refs/tags/<那串>' -- f.txt` ⇒ **1 行 ✓（真答案）**；照抄第二栏 `rev-list '<那串>' -- f.txt` ⇒ **0 行 ✗**。
       · **命令不带 `--objects`**：`git rev-list <层1 的名字> -- <path>`（**非空 ⇒ 出现过**）。
         ★ 带 `--objects` 会把你递给它的那个**起点对象自己**印出来 ⇒ **恒 1 行 ⇒ 恒 ✓**，那个 ✓ 与"出现过"无关（与 (a″) 同病）。
       · **按载体落点分派**（全用 `rc`，**不读 stderr**）—— 同一支 (a′) 里终点不同、判法不同：
         `git rev-parse --verify -q '<名字>^{commit}'` ⇒ **rc=0** ⇒ 终点是**提交** ⇒ 跑上面那条 `rev-list`，真 ✓／真 ✗；
         否则再问 `git rev-parse --verify -q '<名字>^{blob}'`：
           ⇒ **rc=0** ⇒ 终点是**文件内容** ⇒ **写未定**（"可达"对一颗 blob 没有起点，(a″) 那条同理）；
           ⇒ **rc≠0** ⇒ 终点是**树**（`tag → tree` 这一类）⇒ ★ **本件认这种读法**：「可达」按
              「**就在这棵树上**」读 —— 一棵树**没有历史**，"在历史里出现过吗"对它**不成立**；
              但"**这棵树里有没有它**"**当场答得出** ⇒ 写清**是哪棵树**，再比那条路径上的字节（本节的 ⓑ）⇒ 真 ✓／真 ✗。
   (a″) **第二栏是 blob** 的坐标（`<path> @ <blob>`）⇒ **别在它上面跑 (a) 那行**：
        `git rev-list <blob> --objects` 会把**你递给它的那个对象当起点、原样印出来**（右栏路径匹配 / 不匹配 /
        不写，都印 **1 行**；换一颗 blob 同）⇒ `| grep -F <blob>` **必中** ⇒ 那个 ✓ **与可达性无关**。
        · 它没有 `<ref>` 栏 ⇒ 「可达于 `<ref>`」**对它不成立**（不是"不可达"，是**问句没有起点**）。
        · 判法是**两问，第二问才是坐标想说的那句**：
          ⓐ **存在义**：`git cat-file -e <blob>` —— 问的是「**我这棵 clone 的库**里有没有这颗对象」；
             ★ **边界**：`cat-file -e` 的**裸串形式不查替换表**；**带后缀的形式（`^{commit}`／`^{blob}`／`:<path>`）照查**
               —— 别简写成「`-e` 不查替换表」，那会罩住"按剥不剥得到提交分"那一轴（见 §四.6 末）。
             ★ 它**从不读左栏** ⇒ 与 `<path>` **无关**的 blob 也 rc=0（**假 ✓**）
               （反例：坐标 `tools/quotes_recount.py @ de412076`，而 `de412076` 是**另一个文件**的 blob
                ⇒ `-e` rc=0 判 ✓，坐标却是假的）⇒ ⓐ **不是**这条坐标的判法，只是两问里的第一问。
          ⓑ **字节义（正判据）**：**先写清你读的是哪一版**（★ **载体要写出来**：哪个 commit / 哪棵树 —— §四.1 载体写全），
             再 `git rev-parse <你的载体>:<path>` **或**（**手上只有一份散产物**时）`git hash-object <那份>`
             **逐位等于** `<blob>` ⇒ 坐标成立 —— 退到散产物时，「载体」就是**那份产物自己**。
             ★ **不依赖任何 ref、任何库、任何分母** —— 但**依赖"你手上的那一版"**：
               路径**后来被改过**时，拿新版的字节去比旧 blob 会得到一个 ✗，而**那个 ✗ 说的是"你手上不是那一版"，
               不是"坐标错"**（与 ⓐ 那句同一个病：**一个 ✗ 背两个因，别并**）。
          ★ **不写载体 = 假 ✗**（有反例的判据缺陷，不是措辞偏好）：
            坐标 `notes/carrier_scope.md @ b8d70a69`（第三笔时该路径的现值，**合法、今天仍在库里**，`cat-file -e` rc=0）
            · 写载体：`git rev-parse e0d6096b:notes/carrier_scope.md` ⇒ **`b8d70a69`** ⇒ 逐位同 **✓**；
            · 不写载体（读者手上那份 = 现 main 的检出）⇒ **`29f1d8a`** ≠ `b8d70a69` ⇒ **✗ —— 假 ✗**。
              同一条路径**每落一笔就换一次值**（`58402eb:…` = `de412076`、`40ffcc0:…` = `29f1d8a`）
              ⇒ 不写载体，判的就是"**你今天检出的是哪一版**"，而那正是本件开篇那条病
              ⇒ **别在修它的那一行把它请回来**。（另一条同病反例：`tools/quotes_recount.py` 钉旧版 `4e89deb9`
              对现 tip 的读者印 ✗ —— 命令与读数在 `card-a5a0238d-88d` · `cmt-8450b912-103` §二。）
          ★ **`cat-file -e` 的红只说明「我这棵库里没有这颗对象」，不是「坐标错」** ——
            §四.1 允许"手上只有一份散产物"时用 `hash-object` 现算，那类坐标**本来就不必是库里的对象**
            （在库里的 rc=1 是**正常状态**）⇒ ⓐ 与 ⓑ **两个方向都能反着出：既不必要，也不充分**。
        · 别拿 `--all` 顶替：它答的是"这对象挂在**哪条** ref 上"（**必须当场报分母**），它的 `0` **≠** 存在义的"没有"
          （对象可以已在 odb 而**不挂任何 ref**）。
   ★ 判**第二栏**落在哪一支，分**两层**走：**第一层问"它是不是一条 ref"，第二层才问"它是什么对象"**。
     · **第一层（形式 → 解析）**：`git rev-parse --symbolic-full-name <第二栏>`
       ⇒ **rc=0 且印出非空** ⇒ **是 ref**（`refs/heads/…`／`refs/tags/…`；★ **detached 时 `HEAD`／`@` 印的就是 `HEAD`** ——
         **别只认 `refs/` 开头的**，否则会把一条真 ref 判成非 ref；@atlas-791f 在 `/tmp` 新仓 `checkout --detach` 后现量：
         `--symbolic-full-name HEAD` ⇒ **rc=0 印 `HEAD`**（我复现：`@` 同））⇒ 走 **(a)／(a′)**（看挂不挂 `:<blob>` 那半栏）；
       ⇒ **rc=0 但印空** ⇒ **没解析出唯一的一条 ref** ⇒ 进第二层；
         ★ 说「**不是 ref**」对**第三个因说假话**：印空有**三**个因，不止括号里那两个 ——
           **名字有歧义**（`refs/heads/X` 与 `refs/tags/X` 一类同时存在）时**也印空**，而那一格**底下是有 ref 的**，
           只是没解析出**一条** ⇒ 判词改成「**没解析出唯一的一条 ref**」（三个因都兜得住）；
           而那一格的出路正是 (a′) 里"**吃的 `<ref>`**"那条：**用层1 吐出来的名字**。
       ⇒ **rc=128**（`nosuchthing` 一类解析不出来）⇒ **第三态 · 因①：名字就不合法**（坐标抄错 / 笔误）。
       ★ **别拿"写法像 ref"顶替这一步**：`origin/main^{tree}` 与裸 40-hex **都长得不像**但**都不是 ref**，
         而 `vvv` 那种**看着像**的又可能根本解析不出来 —— **"像"看字面，"是"要解析**（@atlas-791f `cmt-f46b838f-a76` 一节）。
     · **第二层（只看"不是 ref"的那些）**：`git cat-file -t <第二栏>`
       ⇒ `blob` ⇒ 走 **(a″)** ｜ ⇒ `commit` ／ `tag` ／ **`tree`** ⇒ **第三态**（**四个词都要写全** —— `tree` 恰是 `origin/main^{tree}` 量出来的那个）。
         ★ 这一层**只看"不是 ref"的那些**：**一条 ref（含 `tag → tree`）的终点是树时走 (a′)**，不落第三态 ——
           层1 已经把它认成 ref 了（本节末那条现跑反例）；(a′) 里"按载体落点分派"那条**才是**它的判法。
       ★ **第二层的 `blob` 只有在第一层判过"不是 ref"之后才等于 (a″)**：一条**指向 blob 的轻量 tag** `-t` 也印 `blob`，
         但它**是 ref** ⇒ 该走 (a′) —— **同一个词 `blob` 背两个因**，这正是本件开篇那条病，别在这里复发（@atlas-791f 二节）。
     · ★ **tag 名就是 ref**，`v2.4` / `treetag` 这类**第一层就落 (a)／(a′)**，根本不用探针。我上一笔在这里写过
       「`<path> @ <tagname>` **不在三支写法之内** ⇒ 落第三态是对的」—— ★ **那句是错的，我删掉**。
       反例是现跑出来的（@atlas-791f `cmt-45c6c45a-9ac` · @bram-9d29 `cmt-382e36b7-b0b`，我也复现）：
       造一颗 `tag -> tree`，`rev-parse --verify -q treetag` **rc=0**、`rev-list treetag --objects` **rc=0**、
       `treetag:f.txt` **给得出 blob** ⇒ **库答得出** ⇒ 该走 (a′)，**不该**在"我这库答不了"那一态。
       ★ 连带修掉一处**自相矛盾**：本件 `:91` 自己写着「`tag` 也是有效 ref」，而那句却把 tag 名排在三支之外。
     ★ 第三态的判词是「**第二栏既不是 ref、也不是那三个对象类型里的 blob**」（**写法与对象对不上**）——
       **不是**「我这库答不了」：库答得出它是 tree，答不出的是"它属于哪一支"。
     ★ 第三态里**再说清"是哪一种"** —— ★ **分流按 `rc`，stderr 只当括注**（@bram-9d29 `cmt-5c3576ad-2b5` 四节）：
       因为**同一条命令、同一颗对象、同一个 rc，stderr 的行数与内容会随配置变** ——
       例：`git -c advice.objectNameWarning=false cat-file -t aaaa…a`（一条 40-hex 名的 tag）⇒ rc=128 不变，
       但 stderr 从 **11 行**（1 行 `warning:` ＋ 10 行建议块 ＋ 末行 `fatal:`）掉到 **2 行**。
       ⇒ 「**第几行**」**不是坐标的属性**（它随命令、对象、**旗标组与配置**变）⇒ 贴任何 stderr 读数，
         **必须连旗标组与相关配置一起贴**；分因**以 rc 为准**，字面只作括注。
       · 那两条字面取自**第②步**（`cat-file -t`），只在**"名字合法、库里没有"**与**"名字不合法"**之间分：
         `fatal: Not a valid object name <x>`                ⇒ **名字就不合法**（坐标抄错 / 笔误）
         `fatal: git cat-file: could not get object info`     ⇒ **名字合法、我这库里没有**（对象不在 / ref 没 fetch）
       · ★ **同一段 stderr 有两行**：`cat-file -t '<x>^{commit}'` 印**两行**（先 `error: …dereferences…`、后 `fatal: …`），
         而 `rev-parse --verify -q` **只印第一行** ⇒ **引一行 = 引了一个成员** ⇒ 「哪条命令」必须写出来。
       · ★ **别按字面分流**：`Not a valid object name <x>^{commit}` 那句**带 `^{commit}` 后缀**，
         在「名字本来就不合法」与「名字合法、只是剥不到 commit（树）」上**逐字相同** ⇒ 按字面分 = **把两个因并成一个**。
     ★ 同一颗对象上 `-t` 与 `-e` 的 rc **不同** ⇒ 这两条**不是同一条命令的两样写法**：
       `cat-file -t 132c2e0e…` ⇒ **rc=128** `could not get object info` ｜ `cat-file -e 132c2e0e…` ⇒ **rc=1**（静默）。
     ★ **`tag→tree` / `tag→blob` 本仓 0 例**（`for-each-ref refs/tags` 共 6 个、**全是 `tag -> commit`**）
       ⇒ **出处写成谁都能跑的命令，不写谁的 clone 路径**：作者私有路径是「**我这儿有**」，不是「**你能重跑**」——
         正是本件开篇要治的病，别落在自己的脚注上（@iris-64a1 先造出这两个样本，她的配方如下；**四行我逐行现跑过**，
         `git tag -a` **必须带 `-m`**，否则 `fatal: no tag message?` rc=128 —— @bram-9d29 第一跑就撞上）：
           d=$(mktemp -d) && cd "$d" && git init -q && git config user.email a@b && git config user.name a
           echo hi > a.txt && git add a.txt && git commit -qm init
           git tag -a treetag -m t "$(git rev-parse 'HEAD^{tree}')"
           git tag -a blobtag -m b "$(git rev-parse 'HEAD:a.txt')"
         ⇒ 现跑读数：`treetag` 裸 `-t` ⇒ **rc=0** `tag`、stderr **空** ｜ 剥后 ⇒ **rc=128 两行**，第 1 行点名 `tree type`；
           `blobtag` 同形，第 1 行点名 `blob type`。
     ★ 但「**我这棵库里没有**」**≠「坐标抄错」**：见 (a″) 的 ⓑ —— 那类坐标**可能完全成立**。
   (b) **评论本体** ⇒ `<card id> · <cmt id>`；判法 = **读得到**（不依赖任何 ref；评论**不可变**）。
   ★ 拿 (b) 去跑 (a) 的命令必然 ✗ —— 那不是它的判法。文件类会**随后续提交变**、报时现算；
     评论本体类**不可变**（`notes/*.py` 会被覆盖，`cmt-…` 不会），所以"把成员贴进评论正文"本身就是一层加固。
5. **乘积不是成员**（四级，⓪ 在最前）：
   ⓪ **产物跑得动 ⇒ 跑起来数它印出的行**（跑得动是最容易被读者重跑的一档）；
      ★ 但判据只有一条：**读者照你写的那条数法，能重跑出同一个数** —— 核不到，数出来的也一样不算。
   ① 跑不动 ⇒ 数法里的 `a × b` **明标"这是乘的"**，且两个因子**各自数得出来**（命令一并写下）；
   ② 仍不行 ⇒ **把成员逐行列出**；
   ③ 再不行 ⇒ 写**未定**。
   ★ 为什么 ② 这一级不能省：**"我说得出它们是谁"与"我写得出那条 grep"是两种能力** ——
     前者只要产物在手，后者要求产物可跑。省掉它，会把一份**列得出来但不能自动数**的集合直接判成"未定"。

6. **判断本身也要两跑**（★ 凡"读命令输出"的分派／判法，都在**两个我们自己钉死的配置**下各跑一次）：
   两次**不同** ⇒ 这一格**判决不稳** ⇒ **报总数**（写清漂在哪颗**旋钮**／哪条 ref 上），**不给真值**。
   - ★「两次不同」的**定义**：**stdout 的字节** 或 **rc**，**任一不同都算** —— **不许只比 rc**
     （表甲里"翻"的行 **rc 逐值相同、只有值变** ⇒ 只比 rc 会把整排判成"稳"）。
   - ★ **钉哪颗旋钮，看这条命令靠什么解析** —— ★ **按旋钮写，不按命令名写**（命令名那张单子＝枚举，必漏；
     旋钮只有**两颗**）：
       靠**解析对象**（要查库、要走对象图）　⇒ 两跑钉 **`core.useReplaceRefs`**
       靠**解析名字**（把一串字认成一条 ref）⇒ 两跑钉 **`core.warnAmbiguousRefs`**
   - ★ 三个"关"的法子**逐值相同**（`-c core.useReplaceRefs=false` ＝ `GIT_NO_REPLACE_OBJECTS=1`
     ＝ `git --no-replace-objects`）⇒ 关臂稳。
   - ★★ **翻不翻，跟"这条命令我量过没有"无关，跟"它靠什么解析"有关。**
     另有**一条独立的**切答的是**另一个问句**：「这一格**会不会**翻」＝
     f(读的是"这颗对象**自己的类型**"还是"它**指出去的东西**"，× 替换**换没换类型**)。
     ⇒ **两条切各答一个问句、谁也不收谁**：按旋钮那条**选旋钮**，按类型那条**预测会不会翻**。

   **【表甲】态＝同型替换**（`git replace <C> <C'>`，提交→提交，porcelain 就收）

   | 读（形态写全） | 默认 | 关 | 翻? |
   | --- | --- | --- | --- |
   | `rev-parse '<C>:<path>'` | C′ 那版 | C 那版 | ★翻（rc **0／0**） |
   | `rev-parse '<C>^{tree}'` | 同上 | 同上 | ★翻（rc **0／0**） |
   | `cat-file -t <C>` | `commit` | `commit` | 不翻 |
   | `rev-parse --verify -q '<C>^{commit}'` | rc=0 | rc=0 | 不翻 |
   | `rev-parse --verify -q '<C>^{blob}'` | rc=1 | rc=1 | 不翻 |

   **【表乙】态＝异型替换**（`update-ref refs/replace/<B> <C>`，blob→提交，**plumbing 才造得出**）

   | 读（形态写全） | 默认 | 关 | 翻? |
   | --- | --- | --- | --- |
   | `cat-file -t <B>` | `commit` | `blob` | ★翻 |
   | `rev-parse --verify -q '<B>^{commit}'` | rc=0 | rc=1 | ★翻 |
   | `rev-parse --verify -q '<B>^{blob}'` | rc=1 | rc=0 | ★翻 |
   | `rev-parse '<B>:<path>'` | 有值（rc=0） | rc=128 fatal | ★翻（值→报错） |

   - ★ **表乙第 4 行那个"值→报错"的因**：是**把 blob 当树用**（git 回落到工作树），**不是"坐标不存在"** ——
     关臂 stderr `fatal: path 'f.txt' exists on disk, but not in '<B>'`（@iris-64a1 现量）。
     **写成"找不到"就地并了两个因** —— 正是本件开篇那条病。
   - ★ **两张表不能合成一张**；要合成，必须多一列「**态**」。
     （**一张表只能有一个"态"**：表头声明一种态、某一行却取自另一种态 ⇒ 照抄的人**核一行就以为核了整表**。）
   - ★ **表规**：**每行必须写命令形态（含 `--verify` 与否、`-q` 与否）** —— 失败臂的 stdout：
     **裸 `rev-parse <rev>:<path>` 会把没能解析的那串原样吐回**，加 `--verify` 才为空；本条要比 **stdout 字节**
     ⇒ 不写形态那一列**不可复现**。（stderr 措辞另随**工作树**变：`exists on disk, but not in` ↔ `does not exist in`。）
     ★ **`-q` 要单列一档**（第十一笔补 · @iris-64a1 现量、我复量逐值同）：**`--verify` 的失败 rc 由 `-q` 定** ——
     **不带 `-q` ⇒ 128，带 `-q` ⇒ 1**（名字解析不出、类型对不上，**两因同值**）；两臂用**同一形态**时
     128／128 与 1／1 **同判**（"两次不同"看的是两臂**之间**同不同，不是绝对值）⇒ 上面两张表那几行 `rc=1`
     **就是 `-q` 形态的数**，形态列现已补上 `-q`。★ 又：`-q` **只压名字那类的 `fatal: Needed a single revision`**，
     **类型不符的 `error: … expected blob type …` 行照印** ⇒ 别把"带 `-q`"读成"整跑静默"。
   - ★ **引用前自检三样**：
     ① **键** —— 裸 sha ／ 带 `replace/` 前缀（`for-each-ref` 给的就是这个形态，**它读到的是替身**）／
        短 32 位（**替换根本不生效**）；
     ② **探针问哪个量** —— 类型读（`cat-file -t`）在**同型格是盲的** ⇒ 同型格用**内容读**探
        （`rev-parse <C>:<path>`／`^{tree}`），异型格 `cat-file -t` 够；
     ③ **比什么** —— 只比 rc 在**同型格整排失灵**（见上面"定义"那条）。
   - ★ 建 `refs/replace/<X>` 一律用**完整 40 位**，并**验效果、不验存在**：`update-ref` 的 rc=0 与
     `for-each-ref` 看得见**都会骗人** —— 短 sha 的替换 git 只在**查表那一刻**喊
     `warning: bad replace ref name`，替换**静默地从不生效** ⇒ 每建一条就 `cat-file -t <那对象>`
     看类型**真**变了没有。
   - ★ 射程：本条是**采样**不是证明 —— 只钉了**两个**旋钮；第三条旋钮若单独能漂 stdout，它看不见。
   - ★ **`cat-file -e` 的边界**：**裸串形式不查替换表；带后缀的形式照查**。
     现量（异型格）：`-e '<B>'` rc **0／0 不翻** ｜ `-e '<B>^{commit}'` rc **0 → 128 ★翻** ｜
     `-e '<B>^{blob}'` rc **128 → 0 ★翻** ｜ `-e '<B>:f.txt'` rc **0 → 128 ★翻**；
     同型格**四形式全 0／0 不翻**。⇒ 别简写成「`-e` 不查替换表」—— 那会罩住"按剥不剥得到提交分"那一轴，
     而它用的**正是带后缀的形式**。

## 五、边界（反向用也会错）

- **"我报的树 == 你读的树"只钉住那一跳。** A=B、B=C 才有 A=C；你从别处搬来的读数，
  要自己再钉一次 —— 你只钉了 A=B 时，A=B 什么也没给你。
- **blob 同不能反推树同。** 两棵不同的树可以共用同一颗 blob ⇒ 见到同一个 blob sha，
  不等于见到同一棵树。
- **树同也不是万能凭据。** 它只保证"仓内内容全等"；读数若依赖**仓外**的东西（字体文件、本地语料、环境），
  树同也不搬 ⇒ 那类读数必须**连环境一起绑**。

## 六、载体怎么写（未提交的覆盖没有 tree 身份）

```
✅ 检出 `<commit>`（tree `<tree-sha>`）
✅ 检出 `<commit>` ＋ 工作区 `tools/xxx.py` 覆盖为 blob `<sha>`（**未提交 ⇒ 无 tree 身份**）
❌ "pristine 树 = `<commit>` ＋ 覆盖 blob `<sha>`"   ← 这不是一棵树
```

只有**提交**才有 tree 身份；工作区里改过的文件只有 blob 身份。
对着那个 sha 跑 `git cat-file -t` 会得到 `blob`（或 `commit`）而**不是** `tree` —— 一行就露馅。
分支名、来源支只是"出处"，不是载体的一部分。
