# 原文补翻流程（新规则动手前必做）

> 来由：2026-10-07 中枢方向（`L24:84-85`）漏了。当初只照 `L17` 的定义写，没翻别处的补充和限制；后来的核对只问『代码对不对得上规则』，没问『规则是不是原文的全部』。小栋问为啥还会犯这样的错。card-a614755c-169 把笔、线段、中枢、分界四样全文补翻了一遍，翻出来的东西记在各文件文末『2026-10-07 全文补翻』一节和 `走势分段.md` 六之三。
> **引号口径**：「」＝原文逐字；『』＝编者的话。

## 什么时候做

任何一条新规则（或者改一条已有规则）**写进 spec 之前**。不管看起来多简单。

## 怎么做

1. **全 108 课搜，不只搜定义那一课。** 先去叠字（`re.sub(r'(.)\1+', r'\1', line)`，语料 105／108 课有源页叠字）再搜，引的时候用原始行、原始行号。关键词要搜宽：概念名＋它的别名＋相关动作（例：中枢 → 中枢／三段／进入／离开／延伸／扩展／扩张／新生）。
2. **答疑也要翻，而且答疑里的限制最容易漏。** 作者的答复（`缠中说禅：` 开头）算原文；提问人的话不算，除非作者认了。
3. **每一处分四类记**：定义／限制／例外／举例。**重点找限制和例外**：定义我们一般不会漏，漏的都是后面课里补的『但是』『准确说』『在……情况下』。
4. **跟 spec 逐条对**：这一处 spec 有没有写、写对没有。没写的、写反的单独列出来。
5. **有冲突就摆出来，不替原文挑**：原文前后说法不一时（例：`L33:9-10` 的 6 段 vs `L32:118` 的 9 段），两处都写进 spec，标明程序用哪个、为什么，由小栋定。
6. **初筛可以让别人或工具做，结论必须本人逐行回原文核过**才算数；引文用 `notes/spec-quotes.py --check` 和 `notes/concepts-pipeline/checkquotes.py` 两把尺都过一遍。
7. 补翻结果贴卡，再动 spec；spec 定了再动引擎（『spec → 引擎 → 独立核 → 前后图 → 上线』）。

## 判据

补翻做完的标志不是『找到了支持我们写法的原文』，而是『**能说出原文里还有哪些限制我们没写，并且每一条都说明了为什么不写或者等谁定**』。
