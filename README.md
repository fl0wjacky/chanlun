# chanlun — 缠论结构分析与概念卡

把《教你炒股票》里"包含处理 → 分型 → 笔 → 线段 → 中枢 → 扩展"这条链实现成可跑、可自检的代码，
并用它做两件事：**分析真实行情**（和闭源指标对账）、**画概念卡**（一张卡讲一个概念）。

## 常用入口

```bash

python3 tools/find_original.py --toc                 # 列 108 课目录

python3 tools/find_original.py 中枢的延伸 -n 5        # 关键词 + 上下文
python3 tools/find_original.py 线段必须 三笔          # 多关键词（全部命中）

python3 tools/fetch_klines.py BTCUSDT 4h --start 2025-10-01 --out btc_4h.json
python3 render/chart_full_smooth.py btc_4h.json --name "BTC/USDT 永续" --tf "4 小时" --px 8 --ph 2400   # BTC 全景顺滑版
python3 tools/extract_chart_pens.py        # 截图 → 笔顶点
python3 render/chart_levels.py             # 出双级别对照图
python3 cards/c05_center.py                # 出某一张概念卡

python3 tools/build_pdf.py                 # 概念卡合集 PDF（先跑上一行）
```

## 引擎不变量（selfcheck 会逐条验证）

| 不变量 | 为什么重要 |
|---|---|
| 标准化序列里相邻两根**不存在包含关系** | 这是"标准化做完了"的定义 |
| 相邻两根的**高点不相等、低点也不相等** | 上一条的等价形式；一旦出现就是标准化有 bug |
| 分型的**类型严格交替** | 顶、底、顶、底…… 位置可以不连续，但类型不会连排 |
| 顶分型「4 条件」版 == 「只看高点」版 | 验证"低点也最高是自动的"这条推论 |
| 底分型「4 条件」版 == 「只看低点」版 | 同上 |
| 笔：类型交替、隔得够（老笔 / 新笔）、顶分型最高K线有一部分高于底分型最低K线 | `check_pens()`（第 77 / 81 课） |
| 笔内**不能再切出**合法的三笔（相等价位取最先一个） | `unsplit_violations()`，独立写的，不调用划笔代码（第 77 课唯一性证明） |
| 笔端点是这一笔的最高 / 最低 | `nonextreme_pens()`，**只报数**：剧烈扩张震荡里偶有回头修正也救不回的（5 组数据合计 ≤2 笔） |
| 中枢区间 = 前三段的 [max 低, min 高]，且 ZG ≥ ZD | 三段确实重叠才有中枢；重叠成一个价位也算（第 54 课） |
| 终结方式按定义重验：三买 / 三卖（离开段从区间里出发、回试不回来）先到则终于离开段之前；否则第一个整段离开的 Z 段按中心定理一终结；都没有才是 live | `check_centers()`，类中枢、线段中枢同一套 |
| 9 段升级：满 9 段有且只有一条升一级记录（满 27 段再加一条），区间**只按前 3^(m+1) 段**三组重叠另算，多出来的段只算震荡、不进高一级区间 | `check_centers()`（第 33 / 64 课；「前」与「尾巴不参与」见记忆要点） |
| 扩展合成：前两个成员不是趋势；区间 = 前三段重算、之后不变；接进来的成员都碰到区间；恰好覆盖全部中枢；级别 = 成员 + 1 | `check_hierarchy()`（第 17 / 42 / 43 / 52 / 54 课） |
| 线段：笔数单数、首尾相接、方向交替；按原文定义独立复核（特征序列包含处理另写一遍） | `check_segments()` / `verify_by_definition()` |

## 记忆要点（踩过的坑）

- **只用最高价、最低价**，开盘收盘不参与任何计算（第 65 课）。
- **方向由「标准化序列的最后两根」决定**，不是看被合并的那两根。
- **合并后的东西是一个区间，没有实体和影线**。
- **分型判定必须在标准化序列上做**，不能拿原始K线图数。
- **笔的端点必须是这一笔的最高 / 最低**（第 66 / 70 / 71 课答疑：「如果不是，那里面一定不只一笔」）。
  一遍扫过去不回头的划法（v1）约 20–30% 的笔违反这条；现在按第 77 课步骤 + 回头修正，逐根喂入时偶尔会连带改前面 1–3 笔。
- **中枢终结：第三类买卖点为主，中心定理一兜底**（第 38 课「第三类买卖点，和中枢延伸的结束是一回事情」）。
  关键是离开段必须**从中枢区间里出发**：v0 只看终点，把「先涨破 ZG、再从上方一路穿过中枢跌破 ZD」误判成三卖；
  v1 改成只用中心定理一，又把离开段算进了前中枢，撑大它的 GG / DD，连接段反向的中枢对永远判不成趋势。
  离开段是连接段，不属于任何中枢（第 49 课；第 54 课答疑「连接的次级别当然要和趋势本身是同向的」）。
- **扩展合成的区间只看前三段**（前中枢、连接段、后中枢，各按高低点），之后接进来的中枢只算震荡（第 52 课答疑、第 54 课算例）；
  区间直接重叠的两个中枢也要合（趋势里的中枢「之间是不会有任何重叠的」）。
- **口径一旦选定一路保持**（第 64 课精度、第 81 课笔标准）：精度写在 `config.TICK`（取交易所最小价位），
  笔默认老笔（`min_gap=4`，第 77 课，缠师自己一直用的），新笔 `pen="new"` 只作对照（**定义在第 81 课正文**
  「就是一笔必须满足以下两个条件……」；同篇答疑说「请去昨天晚上帖子里看」，那份帖子就是这同一篇的正文，见 `core/pen.py`）。
  AAPL 30 分钟只是把精度改成 0.1，线段就会变 —— 改精度等于换口径。
- **笔层的中枢叫「类中枢」**（第 64 课「线段以下是没有中枢的，所以说是类中枢」；第 91 课「笔是不能构成中枢的」），
  正规的最小中枢是线段中枢；类中枢留作对照，因为短数据上线段太少。
- **9 段升级**（第 32 / 33 课）：中枢从形成起满 9 段（3 + 6 段延伸），本级别照样是一个中枢，同时记一个高一级别中枢
  （`z["up"]`）；区间按第 64 课答疑「三个三段结合起来看」：前 9 段按 3+3+3 结成三段，各取高低点再取重叠；满 27 段再升一级
  （9+9+9）。**这三句都是原文的，不是我们定的规则** —— 怎么分组：第 33 课「每 3 段构成一个 5 分钟的中枢」；
  升到哪一级：第 32 课「9 个 30 分钟的延伸，每三个又构成日线级别，三个日线级别自然就是周线级别」；
  **剩下的段去哪：第 52 课答疑「中枢延伸的情况，只看前三段的区间，后面都是震荡」、第 34 课「前三段就是中枢，后面是震荡」。**
  引擎照这三句做：升一级只看**前 3^(m+1) 段**（m = 升的级数，满 9 取前 9 段、满 27 取前 27 段…），
  **多出来的段（n − 3^(m+1)，n=26 时 17 段、n=80 时 53 段）只算震荡、不进高一级区间**。
  第 64 课「三个三段结合起来看」给的是**九段这一例**；把它推广成 3+3+3 的三层、写成"各取高低点再取重叠"，**这一步是我们展开的**。
  满 9 而不是超过 9：第 33 课「6 段的延伸，加上形成中枢本身那三段」（**"= 9"这个总段数读法是我们加的戳**：原文只说"加上形成中枢本身那三段"，
  没说等于 9），而**第 32 课自己的算例**（「9 个 30 分钟的延伸，每三个又构成日线级别，三个日线级别自然就是周线级别」）也是 9 ——
  第 32 课那句「不能超过 9」跟它自己的算例打架，33 课站在算例那一边（详见 `docs/03_裂痕.md` 第 2 节）。
  **「升一级」是本仓的说法、不是原文的词**：原文的动词是「构成」（第 32 课那句就是"每三个又构成日线级别"），
  第 92 课讲同类事时用的词是"升级"（"不会超过 9 个数据，超过了，次级别就要升级了"，092:10-11 —— 源页在"次级/别"之间换行，
  **逐字搜要跨行，所以这里不加引号**；全语料"升级"共 3 处，另两处与中枢无关）。⇒ 字段名 `z["up"]` 保留，只在文字里注明这是本仓的话。
- **买卖点**（`core/signals.py`，按线段中枢或类中枢判）：三买三卖与中枢终结同一口径；一买一卖 = 趋势（相邻中枢「下跌 / 上涨延续」，第 27 课「趋势，一定有至少两个同级别中枢」；
  这一句里的「下跌 / 上涨延续」是**本仓的话**，不是原文的词，`verify_quotes.py` 会把它报成「搜不到」—— 这是账、不是误报，见 `docs/03_裂痕.md` 附二）
  最后一个中枢的离开段创新低（高）且力度小于进入段（**第 24 课只说「柱子面积」**；`斜率` 是本引擎自己加的一把尺，见下面那条），背驰后回拉进中枢才算确认（第 18 / 72 课）；
  **原文自己打了折扣**：第 26 课答疑「那是最标准的情况，85%的情况，当然也有例外的，有些强势的股票，可能第一个中枢就根本不回抽 0 轴也是可能的，因为 MACD 毕竟只是辅助」
  （**例外这句盖不盖到"一买"是我们的读法** —— 作者那段说的是"用 MACD 判断背驰"的一般情况）；
  **⚠️ 原文前提里还有一条本引擎没实现**：第 24 课「B 这个中枢一般会把 MACD 的黄白线(也就是 DIFF 和 DEA)回拉到 0 轴附近」
  （**这条引文折叠了 OCR 叠字** —— 源页逐字是「B 这个中枢枢一般会把…回拉到 0 轴轴附近」，照抄去 grep 会不中），
  第 25 课把它说成必要条件（「用 MACD 判断背驰首先要有黄白线对 0 轴的回拉，**这个都没有，在该级别就不存在什么背驰**」）。
  **缺的就是这一条：黄白线回拉 0 轴，`signals()` 和 `check_signals()` 里都没有。** 两处共用的**力度**判据
  （柱面积 / 斜率）是另一根轴、另归 `card-bbfd7719-0fb` —— 本卡见 `card-4b38e822-441`；
  二买二卖 = 确认的一买之后第二段次级别走势的终点（第 21 课），破一买低点标「弱」。所在那段还没走完的记为待确认。
- **`斜率` 是本引擎自己加的力度尺，不是原文的量**：第 24 课只写「柱子面积」；全 108 课「斜率」只有两处
  （第 55 课「这种通道都是斜率很小的」、第 98 课「类似斜率的上涨」），**都不是**背驰力度的度量
  ⇒ 声明里一律写成"本引擎自己加的"，**不许挂课号**（`measure="slope"` 仍可用，只作对照）。
- **引文注意（不是理论分歧）**：第 27 课那句「肯定不会发生在第一个中枢之后，肯定是至少是第二个中枢之后」**两个从句不能同真**——
  按同页「第二个中枢后就产生背驰的情况，一般占了绝大多数」、「如果在第一个中枢就出现背驰，那不会是真正意义上的背驰」读，
  **第一个「之后」应为「之前」**（这是**我们的读法**，不是原文的字）⇒ 引这句必须连注意一起引，否则会把条件说反（见 `docs/03_裂痕.md` 附二）。
- **全量图配色**：笔与类中枢同色、线段与线段中枢同色，高一级别中枢同色加粗框；项目根目录放 `chart_style.json` 可改（见 `render/style.CHART`）。
- **线段终点不必是段内极值**（第 70 课「没有人规定分段的结束位置一定是最高、最低的」），这不是债务。

## 工作纪律（吃过的亏）

1. **要用原文，先查本地全文**，没有再联网 —— 源站是单页应用，随机会返回目录页，
   判断办法是看 `<title>` 里有没有「第N课」。
   - **源站文本自带重字噪声**（「如果果」「顶顶分型」，约 30 课、2000+ 处，原始页里就有）。
     `find_original.py` 已对两边都「压重字」再匹配；整句仍搜不到时改用 2–4 字短词组合，
     **搜不到 ≠ 原文没有**。引用进卡片时用去掉重字的干净原句。
   - 提取曾把公式里裸的「<」当成标签吃掉（第 20 课中心定理二 ③④ 被截），已修；
     以后改 `to_text()` 后跑 `fetch_chanlun108.py --reparse`，不必重新联网。
2. 每个说法都要能拿引擎回算验证（见 `tools/verify_*.py`）。改引擎或换数据后，跑一遍全部 verify；
   卡上改了数字，同步改 verify 脚本开头的「卡片标称」。
3. 文字宽度要量，不能凭感觉（卡片格宽固定，超了就裁字）。
4. 声称两个东西「相连」时，它们必须在同一张图上相连。
5. **批量替换要限定作用域** —— 按"行尾长相"匹配会误伤函数体内部（踩过一次）。
6. **卡片里的小图坐标一律自己加格子偏移** —— `zigp()` 只吃裸像素 x、不吃 Mini 的框，
   抄同一个 pts 到右边的格子里，折线会叠回左边的格子（踩过一次：卡片 08 的「盘整背驰」格）。

## 卡片脚本的结构

每张卡（`cards/c0*.py` 与两张框架卡）都是同一个形状：

```python
W, H = 1400, 2500                # 卡片尺寸（模块常量，各段函数直接用）
OUTNAME = "c03_笔.png"            # 输出文件名（main 与 build_all 共用）

def draw_anatomy(d): ...         # 一节一个 draw_*，docstring 写节标题
def build():                     # set_size(W, H) → newcard → 各节 → foot，返回 Image
def main():                      # build().save(OUT + OUTNAME)
if __name__ == "__main__": main()
```

- **import 不出图**，可以在别处 `from cards.c05_center import build` 单独复用。
- `build()` 里各节的**调用顺序就是叠放顺序**，调换可能让后画的盖住先画的。
- 实测数据**出图时由引擎现算**，不手抄数字：c06 / c07 走 `cards/zec_data.py`（ZEC 线段中枢为主、笔中枢对照），
  框架卡走 `model_dissent.gap_rows()` 等。刷新数据后跑 `verify_c06_c07.py`：它另算一遍比对，
  并核对卡上无条件写死的定性说法（「扩展占多数」「结构层级大致对应」）是否仍成立。
- 通用片段在 `cards/base.py`：`section()` 整宽分节面板 + 标题标签，`callout()` 整宽半透明强调框，
  `lchip()` 压在线上的带底色小标签。参数对不上（圆角、缩进、描边不同）的地方保留了原写法，
  不要为了用 helper 去改坐标。
- 新增一张卡：照上面的形状写，再在 `build_all.CARDS` 里加一行（模块名, PDF 目录标题）——
  长图和 PDF 的顺序、目录都只认这一处。

## 已知债务

- 本机（macOS）默认字体与原版不同，版式按 Arial Unicode 调过；换回 Droid 时需再目检一遍。
- **一段直接贯穿整个中枢**（从 ZD 之下一路到 ZG 之上，下一段不回来）：按中心定理一字面，这一段仍与区间重叠，算前中枢的延伸；
  于是连接段是反向的那一段，这一对中枢判不成趋势。按第 54 课答疑这是对的，但也可以把贯穿段当连接段 —— 口径待定。
- 笔端点非极值：剧烈扩张震荡里偶有回头修正救不回的（AAPL 30m、ZEC 15m 各 1 笔）；新笔在 ALGO 15 分钟有 1 处
  等价位引起的「可再切」。selfcheck 对前者只报数。
- c09 买点示意图里，一买之后的三笔会被引擎识别成一个新中枢；三买同时高于它和中枢②，判定不受影响，
  但图上「离开中枢② 后回试」的讲法与引擎口径不完全一致。
